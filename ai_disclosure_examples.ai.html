AI Disclosure Examples for BWQ Repository

Metadata keys

Header metadata uses key: value pairs in the host language's comment syntax. The same keys apply everywhere:

KeyPurposeRequired
ai-disclosureAI involvement level: none, ai-assisted, ai-generated, or autonomousAlways
ai-modelModel identifierRecommended (default: big-pickle)
ai-toolTool / agentRecommended (default: opencode)
ai-providerModel providerIf applicable
ai-reviewerReviewer nameLocally
ai-review-dateReview date (ISO)Locally
ai-session-dateAI session datePer session, before its summary
ai-prompt-summarySummary of the key prompts (user input) that generated the file's contentsPer session

Values not set on a file inherit from this file's defaults. The ai-disclosure value itself is never inherited — it must be explicit in every AI-involved file.

Reviewer convention. The examples below use ai-reviewer: (see Git history) as a simplification — Git history provides reviewer identity, date, and granularity for any change. This is not compulsory: a named person is still valid. The ai-review-date is kept in the header as the date of the last file-level review.

Multiple AI sessions per file. Only sessions that affect the file as a whole belong in the header. Sessions that only affect specific sections should be annotated locally near the changed lines, not in the header. Local annotations use the same ai-session-date / ai-prompt-summary pair, without ai-reviewer or ai-review-date (which live only in the header). Within each pair, ai-session-date always precedes its ai-prompt-summary and other session-related entries.

Visible hint (HTML / Markdown). HTML and Markdown files carry a small visible hint near the page header stating the AI involvement level and directing readers to the source comments. The detailed metadata stays in non-visible comments.
