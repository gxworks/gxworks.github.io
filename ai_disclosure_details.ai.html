More structured external conventions using the same four-level vocabulary (none, ai-assisted, ai-generated, autonomous):

  • HTML element-level attribute — https://github.com/dweekly/ai-content-disclosure
    Proposes an ai-disclosure global attribute and <meta name="ai-disclosure"> tag, aligned with the IETF AI-Disclosure header and IPTC Digital Source Type vocabulary. Supports per-element granularity via attribute inheritance and optional ai-model, ai-provider, ai-prompt-url metadata.
  • SPDX-style file headers — https://github.com/ggfevans/ai-disclosure
    Uses SPDX-AI-Disclosure: tags in source-file comments (same vocabulary) plus an optional AI_DISCLOSURE.md with YAML frontmatter at repo root. Supports per-field metadata (SPDX-AI-Model, SPDX-AI-Provider, SPDX-AI-Scope, SPDX-AI-Date) and inheritance from repo default to file override.

The convention in this repo is more verbose but also more informative. The overhead pays for itself given the project is a small POC where provenance matters for fact-checking.

HTML convention for this repo

The standard metadata keys from the summary page apply; HTML also supports direct attribute syntax on the <html> element — see examples below.

Values not set on a file inherit from AI_DISCLOSURE.md. Values not set on an element inherit from the nearest ancestor element. The ai-disclosure level itself is never inherited from AI_DISCLOSURE.md - it must always be explicit in each AI-involved file's header.

An ai-disclosure value of "ai-generated" at the file level means AI-authored with human assistance (prompting, corrections, review). Otherwise, elements inside the file that differ from the file-level value set their own attribute, so a separate "mixed" file-level value is never needed — the file header says what the file as a whole is; local overrides handle the rest.

File header as session summary. The file header's HTML comment lists those AI sessions that affect the file as a whole. Otherwise AI involvement is marked locally. Example:

<!-- ai-disclosure: ai-generated -->
<!-- ai-model: big-pickle -->
<!-- ai-tool: opencode -->
<!-- ai-reviewer: Roland Horsch -->
<!-- ai-review-date: 2026-06-23 -->
<!-- ai-session-date: 2026-05-27 -->
<!-- ai-prompt-summary: AI disclosure conventions page -->
<!-- ai-session-date: 2026-06-23 -->
<!-- ai-prompt-summary: added external convention references -->
<!-- ai-session-date: 2026-06-23 -->
<!-- ai-prompt-summary: extended HTML disclosure convention -->
<!-- ai-session-date: 2026-06-23 -->
<!-- ai-prompt-summary: Java key-value comment format convention -->

Multiple AI sessions per file. When a file is built from several AI sessions (e.g. timekeeping.ai.html), list them as ai-session-date / ai-prompt-summary pairs in the header comments or locally, following the same key-value format used in Java _AI files.

Equivalent convention for Java (and other languages)

The HTML convention uses tag attributes for structured metadata. For languages without such a mechanism, the same information can be carried in standardized comment lines at the file header, with inline comments for local overrides. A consistent key-value format works across all languages and stays trivially grep-able:

// ai-disclosure: ai-generated
// ai-model: big-pickle
// ai-tool: opencode
// ai-reviewer: Roland Horsch
// ai-review-date: 2026-05-07
// ai-prompt-summary: roundForRxxUsage() tests

The keys match the HTML attribute names exactly, keeping the convention uniform regardless of language. When a file is built from multiple AI sessions, list them as ai-session-date entries after the single ai-review-date. Only ai-disclosure is shared at file level; each session brings its own ai-prompt-summary and, if they differ from the file-level values, its own ai-model and ai-tool etc. Within each session block ai-session-date always precedes its further entries:

// ai-disclosure: ai-generated
// ai-model: big-pickle
// ai-tool: opencode
// ai-reviewer: Roland Horsch
// ai-review-date: 2026-05-26
// ai-session-date: 2026-05-23
// ai-prompt-summary: initial description
// ai-session-date: 2026-05-25
// ai-prompt-summary: row updates, date rounding
// ai-session-date: 2026-05-26
// ai-prompt-summary: split from localhost.run

Custom annotations (e.g. @AiDisclosure("ai-assisted")) would be the more structured equivalent, but comments keep the barrier low and avoid a dependency. The _AI / .ai filename suffix works alongside either approach to make AI-generated files visible at the filesystem level.
